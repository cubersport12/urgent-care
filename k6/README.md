# Нагрузочный тест мобильного API

`scripts/mobile-read.js` моделирует мобильный сценарий: пользователь загружает корневые папки, заходит в папку и её подпапки, загружает статьи/тесты и открывает случайный доступный материал. После открытия есть пауза на чтение; между переходами — короткие паузы. Все действия только GET.

Перед нагрузкой скрипт входит администратором, получает список пользователей, создаёт только отсутствующие `k6-load-001@example.com` … `k6-load-100@example.com`, затем входит каждым аккаунтом и сохраняет сессии только в памяти запуска k6. Повторный запуск использует уже созданных пользователей. Существующие аккаунты с другими паролями не изменяются; если их пароль не совпадает с `TEST_USER_PASSWORD`, подготовка завершится ошибкой.

Создание аккаунтов и получение сессий идёт через API перед началом замеров. Используйте только локальную тестовую базу: тестовые пользователи остаются в ней после теста. Не запускайте против production.

Откройте PowerShell после запуска Docker и API из корня репозитория:

```powershell
$env:BASE_URL = 'http://localhost:8000'
$env:ADMIN_EMAIL = 'test@yandex.ru'
$adminCredential = Get-Credential -UserName $env:ADMIN_EMAIL -Message 'Введите пароль локального администратора'
$env:ADMIN_PASSWORD = $adminCredential.GetNetworkCredential().Password
$env:TEST_USER_PASSWORD = Read-Host 'Задайте пароль тестовых пользователей'
$env:TEST_USER_DOMAIN = 'example.com'
$k6 = 'C:/Users/cubersport12/.local/k6/k6-v2.3.0-windows-amd64/k6.exe'
```

Сначала прогоните smoke на одном виртуальном пользователе. Он создаст/переиспользует только `k6-load-001`:

```powershell
$env:SMOKE = '1'
$env:REPORT_NAME = 'smoke'
& $k6 run k6/scripts/mobile-read.js
```

Затем запустите профиль на 100 пользователей (разгон 2 минуты, плато 5 минут, снижение 1 минуту):

```powershell
Remove-Item Env:SMOKE -ErrorAction SilentlyContinue
Remove-Item Env:REPORT_NAME -ErrorAction SilentlyContinue
& $k6 run k6/scripts/mobile-read.js
```

После полного прогона отчёты появятся в `k6/reports/latest.html` и `k6/reports/latest.json`; smoke сохраняется отдельно в `k6/reports/smoke.html` и `smoke.json`. В отчётах будут число запросов, RPS, доля ошибок, успешные/неуспешные проверки, средняя задержка, p95/p99 и задержки по типам действий (папки, список статей/тестов, открытие статьи/теста). Следующий полный запуск перезапишет `latest` отчёты.

Пороговые значения пока стартовые: ошибки менее 1%, p95 ниже 1 с, p99 ниже 2 с. Их следует скорректировать под ожидаемые требования. Логин 100 пользователей выполняется один раз перед замерами. Сценарий проверяет API навигации и чтения, но не воспроизводит рендеринг интерфейса и прохождение тестов.
