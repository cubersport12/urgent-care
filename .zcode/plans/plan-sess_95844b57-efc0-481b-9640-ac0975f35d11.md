# План: 5 фич (backend + конструктор + мобильное приложение)

## 1. Файлы в наградах (сертификаты)

**Backend**
- `backend/app/models/achievement.py` → `Reward.files: JSONB | None` — список media-путей (`public/rewards/{guid}.{ext}`). Миграция `backend/alembic/versions/014_reward_files.py`.
- `backend/app/schemas/achievements.py` → `files: list[str] | None` в `RewardOut`, `RewardCreate`, `RewardUpdate`, `RewardMeOut`.
- Эндпоинты не добавляем: загрузка через существующий админский `POST /api/v1/media`, раздача через существующий `GET /api/v1/media/{path}` (Bearer).

**Конструктор (content-builder-web-app)**
- `rewards-editor.component.ts` (`RewardEditDialogComponent`): блок «Файлы» — мультизагрузка (`input[type=file] multiple`, паттерн `_onFile` + `AppFilesStorageService.uploadFile` с ключом `public/rewards/${guid}.${ext}`), список прикреплённых с кнопкой удаления, миниатюра для изображений (`downloadFile` + `URL.createObjectURL`). Поле `files` в payload create/update. Регенерация SDK (`npm run sync-and-generate-api`).

**Мобильное (mobile-app)**
- Раздел НАГРАДЫ в `app/(tabs)/profile/achievements.tsx`: у разблокированной награды список файлов (иконка типа + имя), тап → просмотр: изображение — модальный просмотрщик (`expo-image`), pdf — существующий `PdfView`. Кнопка «Скачать/Поделиться»: скачивание в кэш `expo-file-system` + системный шерит через `expo-sharing` (`npx expo install expo-sharing`) — так файл сохраняется в «Файлы»/Галерею.
- Новый компонент `components/file-viewer.tsx` + хук `hooks/api/useRewardAttachments` (или расширение `api/achievements.ts`). Регенерация SDK.

## 2. QR-код пользователя

**Backend**
- Новый роутер `backend/app/api/v1/users.py`: `GET /api/v1/users/{user_id}/qr-profile` (требует Bearer). Ответ `QrProfileOut`: `id, fullName, city, rewards: [{title, files}]` (только разблокированные, через `reward_unlock`/`entitlements`), `achievementsCount`, `stats: {articlesRead, testsPassed, rescuesPassed}` (проекция из `stats_from_events`). Регистрация в `api/v1/__init__.py`.
- Содержимое QR — просто `user.id` (UUID).

**Мобильное**
- `npx expo install react-native-qrcode-svg` (рендер через уже установленный `react-native-svg`).
- Роут `app/(tabs)/profile/qr-code.tsx` (регистрация в `profile/_layout.tsx`): карточка с QR (`user.id` из `useAuth()`), ФИО, email. Вход — строка «QR-код» на экране профиля `profile/index.tsx`.

## 3. Досрочное завершение теста + статус завершения

**Мобильное**
- `contexts/test-context.tsx`:
  - `processSkippedQuestions()` — исправление бага: неверными засчитываются **все** неотвеченные вопросы (убрать условие `visitedQuestions.has(...)`).
  - Новый `allQuestionsAnswered()` — у каждого вопроса есть **реальный** ответ пользователя (до досчёта пропущенных).
  - `finishTest(reason: 'user' | 'autoMaxErrors')` — фиксирует причину; итоговый `completionType`: `'full'` (все отвечены, естественное завершение) | `'early'` (ручное завершение/назад при неотвеченных) | `'maxErrors'` (автозавершение).
- Общий хелпер `computeTestOutcome({answers, allAnswered, minScore, maxErrors})` → `{totalScore, totalErrors, isPassed}` — единая точка расчёта (используют persist, live-обновления и экран результатов; дубликат в `test-results-view.tsx:50-68` удалить).
- **Новая формула прохождения**: `isPassed = allAnswered && (minScore == null || totalScore >= minScore) && (maxErrors == null || totalErrors < maxErrors)` — по вашему уточнению: пройдено = отвечено всё И ошибок строго меньше лимита. Досрочное завершение ⇒ есть неотвеченные ⇒ не пройден.
- `hooks/api/useTestResults.ts`: `persistTestCompletion` принимает `completionType`, шлёт его в `POST /test-results` и в `PUT /tests-stats` (`data: {answers, completionType}`).
- `components/test-taking/test-results-view.tsx`: бейдж статуса — «Пройден полностью» / «Завершён досрочно» / «Автозавершение: лимит ошибок».

**Backend**
- `schemas/stats.py`: `completion_type: str | None` (alias `completionType`) в `TestResultCreate/TestResultOut`.
- `services/stats_from_events.py`: `create_test_result` пишет `completion_type` в payload события `finished`; `project_test_results` возвращает его обратно (у старых записей — `null`). `tests-stats.data` — свободный JSON, изменений не требует.

## 4. Автозавершение при достижении лимита ошибок

**Мобильное**
- `components/test-taking-view.tsx` (эффект после каждого ответа `:74-96`): если `test.maxErrors != null && getTotalErrors() >= test.maxErrors` → сразу финализировать без диалога: `finishTest('autoMaxErrors')` → `processSkippedQuestions()` → persist (`completionType='maxErrors'`, `isPassed=false` по формуле из п.3) → показать экран результатов.
- **Конструктор**: ничего — поле «Макс. количество ошибок» (`maxErrors`) уже есть (`test-editor.component.ts:105`).

## 5. Документы для прочтения на экране завершения теста

**Backend**
- `backend/app/api/v1/training.py`: `POST /api/v1/training/test-recommendations`, тело `{testId, wrongQuestionIds?: string[]}`. Логика: текст запроса = `" testName | questionText"` для ошибочных вопросов (если ошибок нет — только имя теста) → `vectors_for_texts` (кэш `embedding_cache`) → `search_similar_articles` → фильтрация тарифов/награды как в `training_me` → дедупликация → топ-5 `RecommendedArticleOut`. Если `embeddings_configured()` = false → пустой список. POST (а не GET), чтобы не зависеть от момента записи события — клиент сам знает ошибочные вопросы сразу.

**Мобильное**
- `components/test-taking/test-results-view.tsx`: под карточкой результата секция «Рекомендуем прочитать» — fetch на монтировании (`testId` + `wrongQuestionIds` из финальных ответов), строки-статьи в стиле «Почитать» из `app/(tabs)/training.tsx:141-160`, тап → `ArticleView` (паттерн `fetchArticle` из `training.tsx:57-63`). Секция скрыта, если список пуст или эмбеддинги не настроены.
